SECTION 1 — OBJECTIVE AND TARGET DEFINITION
--------------------------------------------------------------------------------
Goal: predict whether a loan will DEFAULT WITHIN 12 MONTHS OF ORIGINATION,
using ONLY information that was available at the moment the loan was issued.

Target variable: default_within_12m
    1  -> a verified default (DefaultDate) occurred on/after the origination
          date and strictly before the 12-month anniversary of origination.
    0  -> the ENTIRE 12-month outcome window is observable and no qualifying
          default happened inside it.

Why "within 12 months": it is a fixed, application-time risk horizon that can be
computed identically for every cohort, which makes the historical cohorts
comparable to each other and to the 2020 test cohort.

Crucial correctness rule: a loan whose 12-month window has NOT yet finished at
the snapshot date is IMMATURE. Immature loans are EXCLUDED — they are never
labelled as non-defaults. Treating them as 0 would inject label noise and bias.

SECTION 4 — TARGET CONSTRUCTION AND VALIDATION
--------------------------------------------------------------------------------
  1. Parse dates: LoanDate, DefaultDate (and other date columns) to datetime.
  2. CUTOFF = max(ReportAsOfEOD) = 2021-07-20.
  3. window_end = LoanDate + 12 months.
  4. default_in_window = 1 if LoanDate <= DefaultDate < window_end (else 0).
  5. eligible = default_in_window  OR  (window_end <= CUTOFF and no default).
     i.e. a loan is kept only when its outcome is fully verifiable.

Validation performed (printed in the notebook):
  * No eligible default has a DefaultDate outside its window (0 violations).
  * No eligible non-default has an in-window DefaultDate (0 violations).
  * Example defaulted loans are shown with LoanDate, DefaultDate, window_end.
  * The latest origination date among excluded (immature) loans is inspected and
    is consistent with the immature-window definition.

SECTION 8 — CHRONOLOGICAL TRAIN / VALIDATION / TEST SPLIT
--------------------------------------------------------------------------------
Split is by ORIGINATION DATE (never random), exactly as required:

  Split       Period                       Rows     Non-def(0)  Default(1)  Def-rate
  ---------   --------------------------   -------  ----------  ----------  --------
  Train       2013-01-01 .. 2018-12-31      71,563      49,660      21,903   30.61%

Roles:
  * Train      -> fit base models and candidate hyper-parameters.
  * Validation -> model selection, hyper-parameter tuning, decision-threshold

  * Test       -> touched exactly ONCE, at the very end, for the final report.

Note the rising-then-falling default rate (30.6% -> 29.8% -> 23.5%). The lower
2020 rate raises the majority-class accuracy baseline to 76.54%, which caps how
much "accuracy" headroom any honest model can have.

--------------------------------------------------------------------------------
SECTION 10 — DATA CLEANING AND PREPROCESSING
--------------------------------------------------------------------------------
Implemented as a reproducible scikit-learn ColumnTransformer, fitted on TRAINING
data only (prevents preprocessing leakage):
  * Numeric branch  : median imputation (SimpleImputer).
  * Categorical     : constant imputation ("missing") + OneHotEncoder
                      (handle_unknown='ignore', max_categories=200).
The whole transformer lives inside a Pipeline that is fit only on training rows.

Cleaning steps:
  * Force the 5 mixed-type columns to numeric
    (CreditScoreEsMicroL, CreditScoreEsEquifaxRisk,
     CreditScoreFiAsiakasTietoRiskGrade, CreditScoreEeMini, NrOfDependants).
  * Build the model matrix: numeric columns -> to_numeric; categorical columns ->
    string, with NaN replaced by the literal "missing".

--------------------------------------------------------------------------------
SECTION 11 — FEATURE ENGINEERING (ISSUANCE-TIME ONLY)
--------------------------------------------------------------------------------
Seven transparent ratio/derived features, each computable at application time:
  * dti          = MonthlyPayment / (IncomeTotal / 12)   (debt-to-income proxy)
  * amt_ratio    = Amount / AppliedAmount                (funded vs requested)
  * inc_month    = IncomeTotal / 12
  * loan_inc     = Amount / IncomeTotal                  (loan-to-income)
  * freecash_neg = 1 if FreeCash < 0 else 0
  * loan_month   = month of origination (seasonality)
  * loan_quarter = quarter of origination (seasonality)
All divisions guard against divide-by-zero by replacing +/-inf with NaN, which the
imputer then handles. None of these features uses post-origination information.

SECTION 12 — CLASS IMBALANCE ANALYSIS
--------------------------------------------------------------------------------
  * Natural training balance is reported (~30.6% positives).
  * Scale-pos-weight proxy = negatives / positives (~2.27).
  * Two LightGBM configurations are compared on VALIDATION:

Interpretation: balancing mainly moves the operating point (higher recall, lower
precision). The final operating point is selected on validation.

SECTION 16 — VALIDATION MODEL COMPARISON
--------------------------------------------------------------------------------
All candidates are compared on the SAME 2019 validation set. For each model the

and balanced accuracy so the accuracy/recall trade-off is fully visible.

Outputs: validation_model_comparison.csv + a bar-chart of validation accuracy and
ROC-AUC per model.

Observations of interest for the write-up:
  * Validation ROC-AUC (2019) is clearly higher than the eventual test ROC-AUC

--------------------------------------------------------------------------------
SECTION 17 — FINAL MODEL SELECTION AND REFIT RATIONALE
--------------------------------------------------------------------------------
Selection rule (honest, validation-based):
  * Choose the model with the highest VALIDATION ROC-AUC; break ties by
    validation accuracy and then default recall.

Refit step (standard and legitimate):
  * After the model family, hyper-parameters and decision threshold are FIXED
    using 2019 validation, the chosen model is REFIT on ALL pre-test data
    (2013-2019 = train + validation).
  * Rationale: the 2020 population is closer to 2019 than to 2013, so adding the
    2019 cohort improves generalisation. This does not leak test information:
    the 2020 labels are still never seen until the final evaluation, and no
    choice (model, params, threshold) is made using test data.

--------------------------------------------------------------------------------
SECTION 20 — LIMITATIONS
--------------------------------------------------------------------------------
  1. Class imbalance + high base rate: majority baseline is already 76.5%, so
     accuracy is a compressed metric.
  2. Temporal drift: validation (2019) ROC-AUC >> test (2020) ROC-AUC; the model
     generalises imperfectly across time.
  3. Label noise: DefaultDate may include temporary/cured delinquencies.
  4. Strict leakage-free features deliberately exclude Bondora's own scoring
     fields and every post-origination field, removing strong but invalid signal.
  5. Accuracy alone is the wrong objective under imbalance; PR-AUC and default
     recall matter more, and are reported.

--------------------------------------------------------------------------------
SECTION 21 — CONCLUSION AND 80-85% VERDICT
--------------------------------------------------------------------------------
The project delivers a complete, reproducible, leakage-free pipeline with a
correct chronological split, validation-only model/threshold selection, and a
single honest out-of-time evaluation on 2020.

VERDICT ON THE 80-85% ACCURACY TARGET: NOT ACHIEVED, and NOT SUPPORTED by this
data under a leakage-free, out-of-time protocol. The honest ceiling is close to
the majority baseline (~76.5%) plus a small genuine margin, because:
    majority baseline  = 76.54%
    unavoidable label noise and temporal drift cap further gains.
Reaching 80-85% would require either (a) leakage (post-origination features),
(b) evaluating on a random split instead of the required chronological split, or
(c) fabricating results — all of which were explicitly avoided.
